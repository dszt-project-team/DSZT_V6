# DSZT_V6 行走故障诊断

## 当前策略

- 不使用停车永久锁存。零目标期间每100 ms重发双零速，`stopf`为兼容字段、固定为0；不会因停车时长或一次速度反馈越界而要求重启。
- 心跳全程维护，双OID各100 ms；驱动器心跳超时配置为1000 ms。失联、驱动器故障、转向未就绪及控制源失控仍禁止行走。
- ±50 ERPM仍用于安全重臂及锁车诊断回读的低速条件，不是停车锁存阈值。正常快速换向不等待低速反馈，减速和换向由OID内部速度环执行。
- MAIN1与手动CH3均直接映射有效输入，不叠加油门均值或MCU纵向斜坡；MAIN2保留8点均值。自动端仍需合法PWM、4帧预热和200 ms回中释放。

## 通信与恢复

[RS485分帧](../bsp/communication/bsp_rs485.c)在临界区同步读取HAL时间与接收快照，按完整2 ms空闲取帧，避免任务旧时间与新接收中断产生无符号时间差误判。SBUS、编码器及飞控PWM健康检查同样使用一致时间快照，并处理tick回绕；PWM断流恢复重新预热。

[OID调度器](../modules/drive/front_drive.c)只在锁车、双侧新鲜低速反馈且安全状态空闲时额外回读模式和目标。合法新回包确认模式非速度模式时，废弃双侧缓存和待发目标，进入已有双侧清零、心跳、回中重臂流程，不直接恢复旧非零目标。解锁后的回包只更新诊断，行走不增加模式回读。

这些修复已由真实源码的[主机回归测试](../tests/README.md)覆盖。原外场“行走不响应、转向可用、断电恢复”经车主多次实车测试未再发生，已获验收；由于缺少原故障日志，不能由未再复现反向认定某一修复就是现场唯一根因。

## UART7 定位表

先确保车辆和人员安全，CH5锁车、CH3回中。若车辆静止且安全，尽量在重启前通过115200 / 8N1发送 `DBG OID` 并保存完整连续日志；如发生意外运动，应立即断动力，安全优先于保留记录。

| 观察结果 | 定位方向 |
|---|---|
| `stopf=1` | 当前固件不产生该值；检查是否仍运行旧固件或读取旧日志 |
| `stopf=0`，`sm=1/2/3` | 安全清零/恢复心跳流程；检查是否持续卡在同一步及总线错误 |
| `sm=4/5` | 等待回中重臂/新零速验证；正常恢复需遥控有效、控制源回中及双侧健康低速反馈 |
| `online=0`、`age`增长，`to/crc/bus`增长 | 状态回包或串口/总线异常；同时检查线束、共地与供电 |
| `fault`非零 | 记录左右具体驱动器故障码，按OID手册排查；不要与MCU的`stopf`混淆 |
| `en=0`而以上正常 | 切 `DBG GENERIC` 检查命令`gate`与转向`sr/sf/sh`等其他放行条件 |
| `en=1`且`tgt/tx`非零、`spd`不响应 | 进一步检查驱动器执行、模式、供电与动力接线；UART发送成功不是执行证明 |

重点保存 `stopf、sm、online、fault、age、hb、hbmax、to、crc、bus、tgt、tx、txt、spd、wmiss、exc/ec`。`DBG GENERIC`用于补充遥控及转向门控；切换诊断视图不会驱动电机。额外模式/目标回读仅锁车低速时启用，行走中的旧 `rmode/rtgt` 不代表当前驱动器值。

当前灯带和蜂鸣器共用安全状态分类，已区分遥控保护、锁车授权、等待回中/转向释放/OID重臂及控制就绪；完整映射见[项目Wiki](DSZT_V6_项目总Wiki.md)。灯光和声音用于提示，不替代UART7的具体门控、左右驱动器与通信诊断；没有蜂鸣也不等于已允许行走。

## 验证边界

软件回归与锁车串口检查不替代实车测试。若仍出现不响应，优先保留故障现场日志，区分命令未放行、总线异常与驱动器执行异常，不以重启后恢复作为根因证据。

当前未启用硬件看门狗。软件故障或MCU异常停机不能仅依靠上述应用门控，应保留独立动力切断手段。
