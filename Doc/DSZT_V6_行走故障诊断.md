# DSZT_V6 行走故障诊断

## 问题边界

外场曾出现两次“行走电机不响应、转向仍可操控、整车重启后恢复”，尚无稳定复现方法或故障时UART7记录。本说明区分已确认的软件行为与未确认的现场原因，不将编译或主机测试等同于实车故障闭环。

## 已修复的明确缺陷

`RobotTask()`提前采集的时间可能早于随后UART接收中断记录的时间。原RS485分帧函数直接作无符号减法，例如 `1000 - 1001 = 4294967295`，会把未收完的半帧误判为已空闲2 ms，导致提前取走和清空数据。

[修复实现](../bsp/communication/bsp_rs485.c)：在已有临界区内同步读取当前HAL时间和接收快照，保留第二次快照复核、2 ms空闲条件及tick回绕逻辑。未修改通信周期、控制映射或安全门。

[主机回归测试](../tests/test_rs485_frame_timeout.c)直接执行真实BSP实现：修复前，普通毫秒边界与tick回绕边界均可提前截帧；修复后，两种情况都保留数据并等待完整空闲。此证据确认该软件缺陷已修复，**不能证明它触发了两次外场故障**。当前修复仅通过编译和主机测试，尚未烧录验证。

## 与现象吻合的停车锁存

[停车保护](../application/chassis/oid_stop_guard.h)在双目标连续为零满1500 ms后，只要两侧状态被判健康、任一速度超出±50 ERPM，就置 `stopf=1`。健康判据允许最多500 ms的缓存状态；不要求连续多组新帧，也不以实际零速帧发送完成作为计时起点。

锁存后持续提交零速并拒绝非零行走目标，转向仍独立运行。反馈回零、摇杆回中或切换CH5均不会解除；当前仅MCU重新初始化清除。已停稳很久后出现单次越界反馈，也能触发锁存。[边界测试](../tests/test_oid_stop_guard_field_cases.c)已复现这些源码行为，但现场是否触发仍须 `stopf` 记录确认。

本版本保留现有锁存策略及±50 ERPM / 1500 ms阈值，不自动清锁、不停发心跳。不能通过取消保护来掩盖真实的停车失败、外力滑行或驱动器异常。

## UART7 定位表

先确保车辆和人员安全，CH5锁车、CH3回中。若车辆静止且安全，尽量在重启前通过115200 / 8N1发送 `DBG OID` 并保存完整连续日志；如发生意外运动，应立即断动力，安全优先于保留记录。

| 观察结果 | 定位方向 |
|---|---|
| `stopf=1` | 已确认MCU停车故障锁存；并不自动说明初次越界反馈的原因 |
| `stopf=0`，`sm=1/2/3` | 安全清零/恢复心跳流程；检查是否持续卡在同一步及总线错误 |
| `sm=4/5` | 等待回中重臂/新零速验证；正常恢复需遥控有效、控制源回中及双侧健康低速反馈 |
| `online=0`、`age`增长，`to/crc/bus`增长 | 状态回包或串口/总线异常；同时检查线束、共地与供电 |
| `fault`非零 | 记录左右具体驱动器故障码，按OID手册排查；不要与MCU的`stopf`混淆 |
| `en=0`而以上正常 | 切 `DBG GENERIC` 检查命令`gate`与转向`sr/sf/sh`等其他放行条件 |
| `en=1`且`tgt/tx`非零、`spd`不响应 | 进一步检查驱动器执行、模式、供电与动力接线；UART发送成功不是执行证明 |

重点保存 `stopf、sm、online、fault、age、hb、hbmax、to、crc、bus、tgt、tx、txt、spd、wmiss、exc/ec`。`DBG GENERIC`用于补充遥控及转向门控；切换诊断视图不会驱动电机。额外模式/目标回读仅锁车低速时启用，行走中的旧 `rmode/rtgt` 不代表当前驱动器值。

当前灯带和蜂鸣器未单独提示 `stopf` 或全部安全恢复状态。因此正常模式灯色、没有蜂鸣，不能排除MCU禁止行走。

## 后续验证原则

先获得故障现场记录，再决定是否调整停车判据或增加显式恢复入口。若以后允许运行时清锁，应在明确锁车、回中、通信健康且连续新鲜双侧低速反馈后进行，不可因单帧反馈回零而自动恢复带油门行走。
