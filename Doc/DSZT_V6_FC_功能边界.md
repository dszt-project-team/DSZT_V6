# DSZT_V6_FC 功能边界与移植方案

## 目标

保留 DSZT_V6 的硬件驱动、几何模型、闭环及 OID 通信机制，将上层控制改成飞控唯一来源。左右始终按站在车后向车头看定义，不引入前后换向定义档位。

| 边界 | FC 专用实现 |
|---|---|
| MC7 / SBUS | 移除接收模块、通道映射、模式去毛刺、CH5 授权及相关恢复门；USART1 和其 DMA/中断不再初始化 |
| MAIN1 / MAIN2 | 唯一命令源；MAIN1 最新有效脉宽直通映射，MAIN2 正常闭环保留 8 点均值 |
| 自动释放 | 两路分别连续 4 个有效样本预热，健康且原始/滤波双中位持续 200 ms 并有新样本后释放命令层；转向层另保留 200 ms 回中门 |
| 输入失效 | 任一路离线、脉宽范围错误或检测到新的非法脉冲/超时累计事件，立即撤销授权、清待发非零目标；恢复必须重新双回中 |
| 正常闭环 | 保留双编码器校零、极性、滤波、角度迟滞、PWM 变化率、阿克曼差速及速度收角 |
| 单轮开环 | 编译宏选择左或右；两路仍须健康，MAIN1 持续中位，MAIN2 点动；另一侧刹停，OID 不允许非零输出 |
| OID | 保留全程心跳、零速刷新、模式维护、状态查询、断档清零及重臂验证；不增加永久停车锁存 |
| ABZ 兼容代码 | 保留找 Z 状态机与 `z_fault_rearm_required`，但 `FRONT_DRIVE_AUTO_Z_SEARCH=0`；当前霍尔运行不执行找 Z，不能视为源码已删除 |
| UART7 | 保留 GENERIC / OID / MT6826S / FC / OFF / 查询；移除 SBUS 视图，默认 FC，指令只改变显示 |
| 灯带 / 蜂鸣器 | 改为飞控状态、等待回中、标定及故障提示；移除遥控锁车、手动档及遥控失联语义 |
| 预留接口 | UART8 金属探测盘、USART2、USART6 保留基础初始化；没有金属盘、A22、RK3566 或板载 IMU 业务 |

## 安全恢复与限制

输入故障与转向硬故障分开处理：输入恢复后允许重新双回中；转向编码器异常、目标或反馈越限保持锁存，先排除故障，再重启控制板。不能借助回中自动清除转向硬故障。

OID 心跳断档恢复仍先清旧目标、恢复心跳、再次清零；在飞控健康回中及底层双侧新鲜零速验证通过后，才重新允许行走。正常快速前后换向不等待双轮反馈归零，仍由 OID 内部斜坡执行。

两根 PWM 信号没有独立解锁位、模式位或序号。飞控持续输出合法但错误的目标时，本板无法知道目标过期；必须在飞控端配置未解锁/失控输出，并保留独立物理动力切断。当前未配置独立硬件看门狗，默认 MCU 硬故障处理不能保证及时关闭持续输出的转向 PWM；不得将软件输入保护视为硬件急停。

## 实施与验证范围

应用 / BSP / 模块来自独立 V6 参考工程，CubeMX 配置继承相同 A 板外设后移除 SBUS，实际重新生成。工程只引用本目录中的源文件，维护代码不塞进生成器非用户区。

软件验证包含飞控映射与释放、掉线/坏脉冲、左右开环和闭环、OID 时序及恢复、UART7 命令、灯音状态以及完整 MDK 编译。2026-10-08，使用者确认本 FC 工程多次落地测试效果满足要求。主机桩测试与实测确认分开记录；未逐项报告的故障注入、制动距离和极端工况不作已验证声明。
