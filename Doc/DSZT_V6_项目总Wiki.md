# DSZT_V6 项目 Wiki

本文描述当前固件的功能、接线与运行规则。硬件配置以 [DSZT_V6.ioc](../DSZT_V6.ioc) 为准，控制参数以 [chassis_config.h](../application/chassis/chassis_config.h) 和 [command_config.h](../application/command/command_config.h) 为准。

当前定版：`v6-28deg-baseline-20260926`。车主已确认28°转向参数与双侧零点；固件轴距保持610 mm，580 mm仅作为[几何对比参考](阿克曼参数/DSZT_V6_前驱转向差速标定.md#5-轴距580-mm参考不修改当前固件)。

## 1. 系统概述

DSZT_V6 采用 RoboMaster A 型开发板（STM32F427IIH6）、STM32 HAL、FreeRTOS / CMSIS-RTOS v1，使用 MDK-ARM 编译。底盘为四轮前驱前转向：前轴两台 OID 驱动轮毂电机，两台 5840 电机独立转向并由各自 MT6826S 编码器闭环；后轴固定从动。

车头为两根转向连杆所在的一面，左右按站在车后朝车头看定义，运行期间不切换。

| 功能 | 当前实现 |
|---|---|
| 手动控制 | MC7/SBUS；CH1 转向、CH3 行走、CH5 模式、CH7 速度上限 |
| 飞控控制 | MAIN1 行走、MAIN2 转向；CH5 授权，SBUS 失控保护仍有效 |
| 双转向闭环 | 独立软件零点、输出轴位置比例环、目标限速、编码器健康与角度保护 |
| 双轮行走 | OID 内部速度闭环，A 板分配阿克曼差速目标并监督状态 |
| 状态提示 | 双 WS2812、板载蜂鸣器、UART7 单源只读诊断 |
| 标零维护 | 保留左/右单轮开环模式；当前关闭 |
| 接口预留 | UART8 金属探测盘、USART2、USART6；仅初始化，无业务协议 |
| 不启用功能 | 板载 IMU 业务；无 A22、RK3566 遥测、前后定义切换、舵机及外八控制 |

金属探测盘的数据采集、解析及控制协议尚未实现，不能将串口预留视为探测功能已完成。

## 2. 硬件接线

四台电机的动力均由独立供电板提供，A 板只承担控制、反馈和通信。信号参考地必须共地；动力回流不得经过 A 板细信号地。连接器按实物 1 脚标记计数，线侧与插合侧视图可能镜像。

### 2.1 转向电机与编码器

| 信号 | 左前轮 | 右前轮 |
|---|---|---|
| 5840 PWM（蓝） | J31-5 / PI5 / TIM8_CH1 | J26-1 / PD12 / TIM4_CH1 |
| 5840 FG（黄） | J31-6 / PI6 / TIM8_CH2 | J26-2 / PD13 / TIM4_CH2 |
| 5840 FR（白） | J31-7 / PI7 | J26-3 / PD14 |
| 5840 BRK（绿） | J31-8 / PI2 | J26-4 / PD15 |
| MT6826S OUT/PWM | J31-1 / PA0 / TIM2_CH1 | J26-6 / PH11 / TIM5_CH2 |
| 信号地 | PGND，可用 J30 | PGND，可用 J25 |
| 电机红/黑线 | 独立供电板动力正/负极 | 独立供电板动力正/负极 |

编码器 OUT 与电机 FG 是不同信号，不可混接。电机线色以实际线束信号定义为准。J31/J26 为信号排针，不提供电机动力；编码器 VCC 按模块额定电压供电，禁止直接接 24 V 或未经确认的可调电源。

### 2.2 通信、飞控与灯带

| 模块 | A 板接线 | 用途或配置 |
|---|---|---|
| MC7/SBUS | J43-3 信号、J43-2 5 V、J43-1 GND；板上反相后到 PB7 | USART1，100000 / 8E2，只接收 |
| OID 的 TTL-485 模块 | J2-2 / PD8 TX → 模块 RXD；J2-3 / PD9 RX ← 模块 TXD；J2-1 GND | USART3，115200 / 8N1；J2-4 为 NC |
| 飞控 MAIN1 | J34-7 / PB0 / TIM3_CH3 | 行走 PWM 输入 |
| 飞控 MAIN2 | J34-9 / PB1 / TIM3_CH4 | 转向 PWM 输入 |
| 飞控信号地 | J34-20 / PGND | 与 A 板共地，MAIN 电源正极不接信号针 |
| 左 WS2812 | J27-1 / PA8 数据、J27-3 GND | TIM1_CH1；Pin2 为 NC，灯带另行供电 |
| 右 WS2812 | J33-1 / PE14 数据、J33-3 GND | TIM1_CH4；Pin2 为 NC，灯带另行供电 |
| UART7 诊断 | J38-3 / PE8 TX → USB-TTL RX；J38-4 / PE7 RX ← USB-TTL TX；J38-2 GND | 115200 / 8N1；A 板已供电时不接 USB-TTL VCC |
| 板载蜂鸣器 | PH6 / TIM12_CH1 | 无需外接 |

两台 OID 的 485 A/B 分别并到同一个自动换向 TTL-485 模块，模块再接 USART3；不使用 MCU DE/RE。模块供电与逻辑电平按实物规格确认，不从 J2 的 NC 脚取电。

轮毂线序：动力 U/V/W 对应绿/黄/蓝；霍尔 G/HU/HV/HW/+5V 对应黑/绿/黄/蓝/红。必须先区分动力与霍尔线束，再核对端子；保持各 OID 与其已适配电机成对连接。

### 2.3 预留接口

| 接口 | 接线 | 软件状态 |
|---|---|---|
| 金属探测 UART8 | J37-3 / PE1 TX、J37-4 / PE0 RX、J37-2 GND | 115200 / 8N1，无接收 IRQ/DMA 或协议任务 |
| 金属探测辅助信号 | J34-8 / PC2 输入、J34-10 / PC3 输出 | 应用不读取/切换；PC3 上电低 |
| USART6 | J36-3 / PG14 TX、J36-4 / PG9 RX、J36-2 GND | 115200 / 8N1，无遥测任务 |
| USART2 | J18-4 / PD5 TX、J18-3 / PD6 RX、J18-2 GND | 115200 / 8N1，无业务任务 |

UART 接口为 TTL 信号，RS232/RS485 设备需匹配转换模块。电压、插头和供电注意事项见 [A 板接线手册](DSZT_V6_接线手册/DSZT_V6_A板接线手册.md)。

## 3. 控制模式与操作逻辑

### 3.1 遥控通道

表中 μs 为 SBUS 归一化后的等效脉宽，并非 SBUS 线上的 PWM。

| 通道 | 功能 | 映射 |
|---|---|---|
| CH1 | 手动转向 | 1500±45 为零；1257 / 1757 达到左 / 右满幅；10 ms 采样、3 点均值 |
| CH3 | 手动油门 | 1500±50 为零；扣除死区后，1000～2000 线性映射到 −1000～+1000‰ |
| CH5 | 控制模式 | 900～1200 锁车；1400～1600 手动；1800～2100 飞控自动 |
| CH7 | 手动速度上限 | 1000～2000 线性映射到 100～4900 ERPM |
| CH6 | 无功能 | 不参与方向、刹车或模式控制 |

上电先将 CH5 锁车、CH3 回中。CH5 新档位需连续两个新 SBUS 帧确认；连续两帧非法或不能稳定确认新档位则锁车。进入手动后油门须连续回中 200 ms，转向还须完成自身的回中释放。

SBUS 有效帧包含丢帧或失控标志时立即进入失控门控；无合法帧超过 300 ms 判为离线。失控后重新确认模式并回中；失控持续达到 700 ms 则撤销启动授权，恢复后须先重新锁车、回中。

锁车或失控时：请求双 OID 零速，转向停止并刹车，不主动回正。正常闭环已释放时，CH1 回中才会控制转向回零。

### 3.2 飞控自动

MAIN1 标定为 1260 / 1502 / 1770 μs，死区为 1502±50 μs，使用最新有效脉宽直接映射（均值窗口1），不叠加油门均值或MCU纵向速度斜坡。MAIN2 为 1000 / 1500 / 2000 μs，死区为 1500±15 μs，保持8点滑动平均。

两路在线预热均为连续4个有效样本，与均值窗口独立；正常在线后，MAIN1输入变化不重新等待4帧。超时30 ms，超时或非法脉冲重置滤波与预热；断流后的首个恢复脉冲也必须重新预热，不沿用旧窗口。

两路有效脉宽窗口为800～2200 μs；窗口外判范围故障并撤销自动释放，窗口内超出标定端点才钳位目标。飞控必须输出匹配的PWM信号；长高电平跨越计数器整圈不得伪装成合法短脉冲。

CH5 选择 AUTO_FC 后，两路须健康且同时回中 200 ms 才释放。自动行走上限为 4900 ERPM，不使用 CH1/CH3/CH7 作为运动目标；SBUS 仍负责授权与失控保护。任一路故障、掉线或退出自动模式即撤销释放，恢复后重新预热和回中。

### 3.3 控制链路

```text
手动：CH3 → 死区/线性映射 → CH7 上限 ───────┐
自动：MAIN1最新有效值 → 死区/线性映射 → 4900 上限 ─┤
                                          ↓
                                     基础速度 ERPM
                                          ↓
CH1 三点均值 / MAIN2 八点均值 → 转向指令 ──┬→ 角度增益 → 阿克曼轮角
                                          │              → 连杆换算 → 轴角限速
                                          │              → MT6826S 位置环 → 5840
                                          └→ 差速指令限速 → 角度增益
                                                         → 前轮路径半径比
基础速度 × 左右比例 → 安全门控 → USART3/485 → OID 内部速度环 → 轮毂
```

CH3与MAIN1行走主链路均没有额外均值滤波或A板纵向速度斜坡。当前不等待两轮低速反馈后才允许正反换向，最终加减速由OID内部速度斜坡执行；这不等于电机能够瞬时停车或换向。

## 4. 软件架构与调度

| 层级 | 职责 |
|---|---|
| Core / HAL | CubeMX 外设初始化、中断入口、TIM6 时基、FreeRTOS 启动 |
| bsp | HAL 回调分发、UART/RS485 收发、蜂鸣器硬件封装 |
| modules | SBUS、PWM 输入、编码器、转向位置环、OID/Modbus、WS2812 |
| application | 模式与安全门、底盘目标、灯效、提示音、诊断输出 |

启动顺序：HAL/时钟 → GPIO/DMA/SPI/UART/TIM → `RobotInit()` → FreeRTOS 默认任务。初始化依次注册回调、命令、底盘、灯带、蜂鸣器与诊断。

仅一个普通优先级业务任务，栈深 1024 words；循环执行 `RobotTask()` 后 `osDelay(1)`。每轮顺序为：命令 → 底盘 → 灯带 → 蜂鸣器 → 诊断。HAL 使用 TIM6 的 1 ms 时基，SysTick 专供 FreeRTOS。

| 服务 | 调度或处理方式 |
|---|---|
| SBUS | USART1 DMA 环形接收 64 字节；IDLE 中断先判标志及使能、清标志，再解析新增字节 |
| 飞控 / 编码器 | 定时器输入捕获；中断记录脉宽、更新样本 |
| OID 总线 | 每轮底盘任务先服务收包、超时和发送调度，约 1 ms 调用 |
| 底盘目标 / 转向位置环 | 10 ms 更新 |
| 灯带 | 100 ms 刷新，TIM1 双通道独立 DMA |
| UART7 | OID/SBUS 每 100 ms；综合/编码器/飞控每 200 ms |

上述任务间隔是软件调度目标，不是硬实时延迟上限。UART7 中断异步发送，忙时跳过本条输出；RS485 发送仍使用有限超时的同步 HAL 调用，不应把整个任务描述为完全无阻塞。

## 5. 转向闭环与角度保护

| 参数 | 当前值 |
|---|---:|
| 模式 | 双侧位置闭环，单轮开环关闭 |
| 左 / 右编码器零点 | 3189 / 3073 |
| 轴角目标变化上限 | 300°/s |
| 普通停止 / 重启误差 | 3° / 5° |
| 近零目标（绝对值≤1°）停止 / 重启误差 | 4.5° / 7° |
| 位置比例增益 | 22‰/° |
| 运行占空比范围 / 每 10 ms 变化量 | 300～1000‰ / 50‰ |
| 闭环方向切换等待 | 50 ms |
| 输出轴目标 / 反馈保护 | 80° / 82° |

MT6826S 使用 OUT/PWM 双边沿捕获，TIM2/TIM5 为 1 MHz、32 位计数；有效周期 800～2400 μs，健康超时 100 ms，包含圆周环回及连续性检查。位置反馈是电机输出轴角，不是直接测得的轮胎角。

软件零点存于固件，不写编码器 NVM，不以上电位置自动标零。两侧反馈极性与正误差电机方向均已由配置宏固定。PWM 低电平运行有效，0‰ 对应全高停止；左 J31 为 50 kHz，右 J26 为 25 kHz。FR/BRK 为开漏，BRK 低电平刹车。

目标绝对值超过 80°或反馈绝对值超过 82°触发故障；任侧故障停双侧并禁止行走。锁车清除上层转向故障锁存后，仍须恢复编码器健康及回中释放。保护为输出轴软件阈值，不替代机械止挡。

单轮维护模式由 `CHASSIS_STEER_CALIBRATION_SIDE` 选择：0 双闭环、1 左开环、2 右开环。开环只在手动模式工作，选中轮 250～450‰、另一轮刹停，回中停止，换向前后各等待 300 ms；不执行闭环角度保护。编码器健康旁路仅作用于此开环模式。

## 6. 阿克曼转向与前驱差速

### 6.1 几何及连杆参数

| 参数 | 当前值 |
|---|---:|
| 轴距 L | 610 mm |
| 前 / 后轮距 | 500 / 500 mm |
| 零油门满幅内 / 外轮目标 | 28° / 20.320382° |
| 对应内 / 外输出轴目标 | 76.125212° / 66.915019° |
| 该角度下内 / 外前轮速度比 | 0.739702 |

前轮距 W 参与前轴差速计算，后轮距仅作为结构尺寸记录。使用内轮角绝对值，几何关系如下；三角函数计算使用弧度。

```text
a = L / tan(内轮角)
外轮角 = atan(L / (a + W))
内轮路径半径 = sqrt(L² + a²)
外轮路径半径 = sqrt(L² + (a + W)²)
内轮速度 = 基础速度 × 内轮路径半径 / 外轮路径半径
外轮速度 = 基础速度
```

直行两侧比例为 1。左转左轮为内轮，右转右轮为内轮；外轮不额外加速，内轮按比例减速。倒车仅改变公共速度符号，左右身份和转向定义不变。ERPM 比例等同于轮速比例的前提是两侧轮毂电气参数与有效轮径一致。

轮角到输出轴角采用固定线性比例：内侧 `89.719/33`，外侧 `82.325/25`；分母是DSZT_V4.1.0的连杆映射参考，不是当前满舵角，不能随28°满舵参数一起改。当前参数组合已确认定版；轮角为该映射的模型目标，不等于新结构的实测角度，后续改动连杆仍须重新测量行程与余量。

结构回调参考（非当前配置）：旧版满舵内/外轮33°/22.97°，对应输出轴89.72°/75.63°。恢复该行程前必须重新核对机械止挡、连杆映射及保护阈值，不能直接套用当前80°/82°限位。

### 6.2 动态处理

转向增益按基础速度指令的绝对值计算：

```text
gain = 1 − 0.30 × min(|基础速度| / 4900, 1)
```

增益范围 1～0.70，前进和倒车均生效，手动时计入 CH7；依据的是速度指令，不是实测车速。转向通路应用增益后计算轮角、换算轴角，再以 300°/s 限速。差速通路先对归一化转向指令做 1.6/s 限速，再应用同一增益与 2% 死区。

差速由处理后的转向指令计算，不使用编码器实测轴角反算。两条通路稳态一致，快速打舵时瞬态可能不同。零油门满舵对应28°及0.739702比例，但此时两轮速度均为0；基础速度4900 ERPM、满舵稳定后，内轮目标19.6°，比例约0.79214，外/内轮约4900/3881 ERPM。

详细尺寸、角度及结构调整参考见 [双转向与前驱差速参数](阿克曼参数/DSZT_V6_前驱转向差速标定.md)。

## 7. OID 驱动控制

### 7.1 驱动器与总线

| 项目 | 左 / 右 |
|---|---|
| RS485 ID | 1 / 2 |
| 正反方向 | 各驱动器内部适配；MCU 方向系数 +1 / +1 |
| 最大转速 | 均为 4900 ERPM |
| 速度环加 / 减速度 | 均为 4900 / 4900 ERPM/s |
| 驱动器心跳超时 | 均为 1000 ms |

固件不覆盖电机辨识参数。两台 OID 共用 USART3、115200 / 8N1、Modbus RTU；通过 0x06/0x10 写控制寄存器、0x04 读基础状态、0x03 读模式与目标。接收采用逐字节中断入缓冲，任务按空闲间隔判帧。当前为霍尔电机，不执行 ABZ 自动找 Z。

分帧判定在同一临界区采集当前HAL时间与最近收字节时间，并二次核对接收快照，避免调用时刻与中断时刻不一致造成提前截帧。

主要寄存器：0x1770 心跳、0x1771 模式、0x1773～0x1774 有符号32位目标 ERPM、0x1775 占空比；从0x1388起读取9个基础状态寄存器。状态须通过从站ID、功能码、长度与CRC检查，才更新在线与故障信息。

### 7.2 关键时序

| 项目 | 当前设置 |
|---|---:|
| 接收帧空闲判定 | 2 ms |
| 主站成功发送间隔 | 至少 8 ms |
| 单次 HAL 发送超时参数 | 10 ms |
| 每侧心跳 / 双侧状态组目标周期 | 100 ms / 100 ms |
| 单次状态或模式目标读回超时 | 50 ms |
| 本机心跳发送断档阈值 | 800 ms |
| 基础状态健康期限 / 启动状态宽限 | 500 ms / 1000 ms |
| 停车双零速重发 | 100 ms |
| 停车永久锁存 | 不启用；反馈越出±50 ERPM不会触发必须重启的停车锁存 |
| 额外模式/目标回读最小间隔 | 250 ms，左右交替 |

心跳值逐台按1/2交替；锁车、手动、自动及等待重臂时均维护，不以停止心跳作为正常停车方式。启动或恢复时执行前清零、恢复心跳、后清零序列。

总线先处理收包和超时；已发出的读事务等待响应或50 ms超时后，才继续发帧。其后依次处理安全清零、到期心跳、紧急零速，再在普通双轮目标组边界插入到期状态查询，最后利用余量做额外回读。新读事务须预留完整超时及两个心跳时隙。紧急零速仍可能等待正在进行的读事务，不能理解为无延迟硬件急停。

正常目标按同一代左右快照分帧下发，首发侧交替。模式缓存为速度模式时使用两帧目标；模式未知时先双侧零速、写速度模式，再发送目标。首侧目标发送前允许合并最新指令；首侧发送后完成同代双侧目标，再接收新一代，避免积压旧指令。

模式缓存依据 UART 发送成功更新，不等于驱动器执行确认。额外模式/目标回读仅在锁车、双侧反馈不旧于200 ms且处于±50 ERPM、安全状态空闲时进行；行走期间暂停，基础状态和心跳继续。

合法新回读确认任侧模式不是速度模式，且应用仍允许锁车低速回读时，废弃双侧模式缓存和待发目标，进入既有双侧清零、心跳及回中重臂流程；不直接恢复旧非零目标。未请求、超时或CRC错误回包不触发恢复；解锁后到达的模式回包仅更新诊断。

### 7.3 安全状态与放行

```text
启动 / OID状态异常 / 心跳发送断档
  → PRE_CLEAR：双侧零速、零占空比及安全模式写入
  → RESTORE_HEARTBEAT：双侧恢复交替心跳
  → POST_CLEAR：再次清除双侧目标
  → WAIT_REARM：保持心跳/零速，等待控制源回中与健康恢复
  → WAIT_VERIFY：读取重臂后的新状态，双侧无故障且在±50 ERPM
  → IDLE：允许上层安全门申请运动
```

非零行走需同时满足：参数与输出开关开启、控制源获准、转向标零维护模式关闭、零点及连杆确认、双编码器健康、双位置环处于HOLD运行态、双OID健康且安全状态为IDLE。HOLD是位置环运行状态，不表示两轮已经精确到达目标角。

零目标期间每100 ms重发双零速，不再以停车时长及单次反馈速度锁存行走禁止。新运动请求仍须通过全部正常安全门；`stopf`仅为兼容旧日志保留，固定为0。心跳、失联清零、驱动器故障和回中重臂保持有效。

OID清零序列、写应答和重臂的±50 ERPM窗口不等同于机械制动或绝对静止证明。出现锁车后持续转动等异常，应切断动力并检查。故障定位及恢复边界见[行走故障诊断](DSZT_V6_行走故障诊断.md)。

## 8. UART7 诊断

### 8.1 切换命令

115200 / 8N1，默认输出OID。命令大写、以换行结束；只切诊断视图，不改变控制模式、不写参数、不驱动电机。重启恢复编译默认值。

| 命令 | 诊断编号 | 行前缀 / 内容 | 周期 |
|---|---:|---|---:|
| `DBG GENERIC` | 0 | `V6`，综合状态 | 200 ms |
| `DBG OID` | 1 | `OID`，双驱动器及总线 | 100 ms |
| `DBG SBUS` | 4 | `SBUS`，遥控与模式门控 | 100 ms |
| `DBG MT6826S` | 5 | `MT6826S`，转向与编码器 | 200 ms |
| `DBG FC` | 7 | `FC`，飞控PWM输入 | 200 ms |
| `DBG OFF` | 255 | 停止周期输出，仍响应命令 | — |
| `DBG?` / `DBG HELP` | 不改变 | 查询诊断编号和命令列表 | 按请求 |

成功或查询返回 `DBG OK mode=... readonly=1 commands=...`；非法、超长或损坏命令返回 `DBG ERR`，不改变视图。此处 `mode` 是诊断编号；状态行中的 `mode` 则是车辆模式，二者不可混用。

### 8.2 公共字段与编号

| 字段 | 含义 / 单位 |
|---|---|
| `t` | 当前HAL时间戳，ms；重启归零，32位自然回绕 |
| `rc` | SBUS在线标志，1在线、0离线；还需结合fs |
| `fs` | 遥控失控或丢帧标志，1表示禁止执行运动指令 |
| `mode` | 车辆模式：0锁车、1手动、2飞控自动 |
| `gate` | 命令安全门：0就绪、1遥控失控、2等待启动锁车授权、3模式未确认、4等待油门回中 |
| `param` | 整车参数确认开关；不是动态健康标志 |
| `en` | OID行走放行：1允许提交目标、0禁止；1不表示正在转动，也不是转向使能位 |

`gate=0` 不等于行走放行：锁车时也可为0。左右成对字段按左/右排列；`tgt/spd`用逗号分隔。计数自本次启动累计并可能回绕，不能仅凭非零累计值判断当前仍有故障。ERPM为电转速，不是轮毂机械RPM。

### 8.3 SBUS模式：遥控输入

输出公共字段 `t/rc/fs/mode/gate`，其余字段如下：

| 字段 | 含义 / 单位 |
|---|---|
| `frames` | 成功解包的合法SBUS帧累计数 |
| `err` | SBUS解析或UART恢复等错误累计数 |
| `ch1/ch3/ch5/ch7` | 对应通道的归一化等效脉宽，约1000～2000 μs，不是SBUS线的实际PWM |
| `filt` | CH1三点均值后的等效脉宽，μs；仅手动路径更新，其他模式可为旧值或初始值 |
| `thr` | 手动油门映射量，−1000～+1000‰；负后退、正前进，未放行时为0 |
| `steer` | 手动转向映射量，−1000～+1000‰；负左、正右，尚未进行速度增益与轴角限速 |
| `lim` | CH7选择的手动速度上限，100～4900 ERPM；自动模式不使用此上限 |
| `calraw` | 1表示单轮开环选用原始CH1；当前双闭环为0 |

控制输入只有在 `rc=1、fs=0` 时有效。自动模式的手动 `thr/steer` 为0，应到FC模式查看MAIN输入。

### 8.4 MT6826S模式：编码器与转向

输出公共字段 `t/en`，其余字段如下：

| 字段 | 含义 / 单位 |
|---|---|
| `cal` | 0正常双闭环、1左单轮开环、2右单轮开环 |
| `encgate` | 单轮开环是否要求编码器健康：0旁路、1要求；不影响双闭环强制健康检查 |
| `sr/sf` | 转向回中释放标志 / 转向故障锁存标志 |
| `raw` | 左/右编码器12位原始值，0～4095 |
| `sh` | 左/右编码器健康标志，1健康 |
| `zero` | 左/右软件零点有效标志，1有效；不是零点数值，也不表示当前在零位 |
| `ang` | 左/右相对软件零点的输出轴反馈角，单位0.1°，例如−123表示−12.3° |
| `at` | 左/右位置环输出轴目标角，单位0.1°，不是轮胎角 |
| `duty` | 左/右低有效运行占空比，‰；0为停止，不代表PWM引脚恒低 |
| `brk` | 左/右刹车状态，1有效；本机电气实现为BRK拉低 |
| `dir` | 左/右电机方向状态0/1，受方向极性宏映射，不直接等于左转/右转 |
| `sched` | 转向通路应用速度增益/死区后的归一化量，‰；不是OID差速斜坡内部量 |
| `gain` | 转向指令增益，‰；正常闭环700～1000，1000表示1倍 |

零点未有效时不把 `ang` 当作已标定角度。当前 `cal=0、encgate=0` 的含义是双闭环运行、保留开环旁路配置，不是忽略编码器。锁车后 `at` 可能保留原目标，应结合 `sr/brk/duty` 判断输出状态。

### 8.5 FC模式：飞控输入

输出公共字段 `t/mode/rc/fs/en`，以及：

| 字段 | 含义 / 顺序 |
|---|---|
| `main1` | MAIN1行走：原始脉宽 / 控制脉宽（窗口1，健康时等于最新有效值）/ 在线 / 故障码 |
| `main2` | MAIN2转向：原始脉宽 / 8点滤波脉宽 / 在线 / 故障码 |
| `rel` | 双路健康且回中200 ms后的自动释放标志，1已释放 |
| `cal` | 当前转向模式，0双闭环、1左开环、2右开环 |

脉宽单位μs，在线1为健康预热完成。故障码来自 `PwmInput_Fault_t`：**0正常、1未就绪、2超时、3范围异常、4预热中**。两路持续监测，但只有车辆 `mode=2` 且通过释放与安全门后才作为控制源。

### 8.6 OID模式：目标、反馈与通信

输出公共字段 `t/param/en`，其余字段如下：

| 字段 | 含义 / 单位 |
|---|---|
| `id` | 左/右Modbus地址，当前1/2 |
| `tgt` | MCU本周期最终左右速度目标，ERPM；尚不等于发送完成 |
| `tx/txt` | 最近成功提交UART的左右速度值，ERPM / 对应HAL时间戳，ms |
| `spd` | 左/右OID基础状态返回的速度，ERPM；有效性需结合age/online |
| `online` | 左/右基础状态新鲜度标志；1不代表fault必为0 |
| `fault` | 左/右驱动器故障码，0无故障；非零按OID故障手册解释 |
| `age` | 左/右基础状态年龄，ms；未取得时4294967295 |
| `hb/hbmax` | 左/右最近一次心跳成功发送的年龄 / 本次启动最大间隔，ms；不证明驱动器收到 |
| `to/crc` | 左/右基础状态请求超时累计 / CRC错误累计 |
| `bus` | RS485接收溢出次数 / UART硬件错误次数，不是左右两侧 |
| `sm` | OID安全状态编号，见下表 |
| `cmd` | 命令挂起标志 / 分帧步骤 / 紧急标志；步骤仅在挂起时有意义 |
| `pre` | 保留的状态读抢占计数；当前不撤销已发读事务，该值保持0 |
| `rmode` | 左/右驱动器控制模式回读；1为速度模式，0为电流、2为占空比；须先确认rage有效 |
| `rtgt/rage` | 左/右驱动器内部速度目标回读，ERPM / 回读年龄，ms；未取得时rage=4294967295 |
| `rto` | 左/右额外模式/目标读回超时累计 |
| `zwr` | 左/右零速帧UART成功发送累计 |
| `sack` | 左/右有效速度写应答累计，包括非零及迟到应答，不逐目标匹配 |
| `wmiss` | 左/右速度写应答未确认累计：超过50 ms、被后续写覆盖或收到对应写异常 |
| `exc/ec` | 左/右Modbus异常应答累计 / 最近异常码；不是OID电机fault码 |
| `stopf` | 兼容字段，当前固定为0；已移除停车永久锁存，不代表其他安全门已放行 |
| `cap` | 编译配置的额外速度上限，ERPM；0表示无附加限制，不是当前CH7值 |
| `ch3` | 原始CH3归一化等效脉宽，μs；自动模式不用于驱动目标 |
| `req` | 经初步运动许可后的公共速度请求，ERPM；尚未差速，也不是最终安全裁决后的tgt |
| `rev` | 可选换向等待标志 / 已确认低速状态组数；当前功能关闭，保持0/0 |
| `rd` | 额外回读许可，1仍需等待安全状态IDLE和总线余量，不表示正在收包 |

| sm | 状态 | 含义 |
|---:|---|---|
| 0 | IDLE | 安全恢复流程空闲，行走仍需上层许可 |
| 1 | PRE_CLEAR | 恢复心跳前清零 |
| 2 | RESTORE_HEARTBEAT | 恢复双侧心跳 |
| 3 | POST_CLEAR | 恢复心跳后再次清零 |
| 4 | WAIT_REARM | 等待健康、回中与重臂 |
| 5 | WAIT_VERIFY | 等待重臂后新鲜双侧低速状态 |

手动/自动行走时额外回读暂停，`rtgt/rmode` 会保留旧值、`rage` 增大；它们不能代表此刻正在执行的目标。诊断关系应按“`tgt` MCU目标 → `tx` 已发送 → `rtgt` 带年龄的寄存器回读 → `spd` 带年龄的速度反馈”区分，而不是视为同一时刻的四个等价值。

### 8.7 GENERIC模式：综合视图

行前缀为 `V6`，用于同时查看各模块；字段按下列分组输出，同名字段沿用前述定义。

| 分组 | 字段及含义 |
|---|---|
| 遥控与模式 | `t、rc、mode、gate、fs`；`thr、steer、lim` 为手动映射量和CH7上限 |
| 行走 | `param、en、tgt、spd、fault`；`oid` 为左右OID在线标志，等同OID视图的online |
| 通信 | `age、hb、to、crc、bus、sm、cmd、pre` |
| 飞控 | `fc1、fc2`，分别等同FC视图main1/main2的“原始/滤波/在线/故障码”；`rel`为自动释放 |
| 转向 | `cal、sr、sf、raw、sh、zero、ang、at、duty、brk、dir、sched、gain` |

综合视图不包含全部OID扩展回读和写应答字段；分析这些状态应切换 `DBG OID`。关闭周期输出使用 `DBG OFF`，查询或恢复输出仍通过上述只读命令完成。

## 9. 灯带与蜂鸣器

双灯带各21颗，当前左右显示相同状态色，优先级从上到下：

| 条件 | 灯效 |
|---|---|
| RC离线 | 低亮红，300 ms交替加入少量绿 |
| 任侧OID故障码非零 | 150 ms红色闪烁 |
| 自动模式MAIN不健康 | 150 ms紫红闪烁 |
| 参数未确认 | 紫色 |
| 手动 / 自动 / 锁车 | 绿 / 青蓝 / 红 |

灯色反映模式或列出的故障条件，不完整覆盖编码器和OID安全恢复等全部安全门；绿色不等于已经允许运动，应以 `en` 与诊断为准。

蜂鸣器提示遥控连接、模式变化、左右OID故障。自动模式的MAIN超时报警须先出现过双路健康状态；飞控超时提示优先于OID故障提示。

## 11. 编译与维护

使用 [MDK工程](../MDK-ARM/DSZT_V6.uvprojx)，目标 `DSZT_V6`，工具链 ARMCC。在 µVision 中 Build/Rebuild；输出为 `MDK-ARM/DSZT_V6/DSZT_V6.axf` 和 `DSZT_V6.hex`。编译与下载是独立操作。

CubeMX 重新生成时保留 USER CODE、自定义源码分组与包含路径；检查 TIM6 HAL 时基、FreeRTOS SysTick、DMA/NVIC，以及 USART1 的IDLE判断、清标志和分发顺序。自检入口见 [tests/README.md](../tests/README.md)；主机测试不替代电机供电、机械限位及故障工况验证。

首次接线或修改零点、方向、几何、限位后，先断电复核，再架空低速检查转向、差速、回中停车和失控保护；确认正常后再开展带载运行。

当前未启用独立/窗口看门狗，HardFault/Error_Handler没有主动撤销转向PWM的统一异常停机路径。软件正常运行下的失联保护不覆盖所有MCU故障，整车仍需独立硬件急停/断动力能力。
